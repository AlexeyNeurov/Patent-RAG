# Архитектура Patent RAG

## Компоненты

| Компонент | Ответственность |
|---|---|
| `app.py` | интерфейс Streamlit, параметры поиска и карточки результатов |
| `src/patent_rag/engine.py` | загрузка индекса, токенизация, поиск, fusion и reranking |
| Qdrant | embeddings и payload патентных документов |
| BM25 | лексическая релевантность по заголовку и реферату |
| NetworkX | ориентированный граф ссылок между патентами |

## Поиск по текстовому запросу

1. Запрос дополняется терминами из доменного словаря синонимов.
2. Модель строит нормализованный embedding расширенного запроса.
3. Qdrant возвращает кандидатов по косинусной близости.
4. BM25 независимо ранжирует тот же корпус по словам запроса. Заголовок документа получает двойной вес за счёт повторения в индексируемом тексте.
5. Два списка объединяются взвешенным Reciprocal Rank Fusion:

   ```text
   RRF(d) = w_vector / (60 + rank_vector) + w_bm25 / (60 + rank_bm25)
   ```

6. Для верхнего кандидата и каждого документа рассчитываются сходство наборов исходящих цитирований (Jaccard) и коцитирование.
7. Итоговый score формируется как `0.85 × RRF + 0.15 × citation_bonus`.

## Поиск похожего патента

Система находит патент по полю `number`, извлекает сохранённый embedding и запрашивает ближайшие векторы. Финальный порядок учитывает семантическое сходство, Jaccard по ссылкам и коцитирование:

```text
score = 0.7 × vector_similarity + 0.2 × citation_jaccard + 0.1 × cocitation
```

## Границы текущей реализации

Индекс загружается в память локальным клиентом Qdrant, BM25 строится при старте приложения по всей коллекции, а граф цитирований собирается из payload. Такой вариант удобен для прототипирования и умеренного корпуса. Для крупной коллекции стоит вынести Qdrant в серверный режим, заранее сохранять лексический индекс и рассчитывать графовые признаки офлайн.
